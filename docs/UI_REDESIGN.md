# Astra 客户端界面重设计（TUI + GUI）

状态：设计稿，待评审。适用范围：客户端 `astra-tui` 及新增 `astra-gui`；服务端控制台见第 10 节。GUI 的可点击原型见 [prototype/gui](../prototype/gui/README.md)（React + Vite，模拟数据）。

本文从功能、用户和操作流程出发，重新设计信息架构、操作语义、TUI 与 GUI，并给出为此需要调整的 crate 划分、管理 IPC 和分阶段落地路线。设计不以现有界面为约束，但每一项都对应到现有能力，不删减核心功能。

---

## 1. 现状分析

### 1.1 软件做什么

Astra 是原生 Rust 的双进程代理客户端：

| 能力域 | 现有实现 | 用户关心的问题 |
|---|---|---|
| 生命周期 | manager 守护进程管理多个 Proxy Core / Rule Core 实例，启动绑定、热重载、完整重启、UAC 提权重启 | “连上了吗？怎么开/关？” |
| 出站 | 节点（SS/VMess/Trojan/VLESS/Hy2/TUIC/SOCKS/HTTP）、代理组（select/auto/fallback/load_balance、动态成员、内置 PROXY/DIRECT/REJECT）、订阅 | “现在走哪个节点？哪个快？” |
| 路由 | Rule Core：域名/IP/GEOIP/GEOSITE/进程/规则集，首条命中；独立模式跳过规则 | “这个网站为什么走/不走代理？” |
| 接管 | 运行时模式（规则/全局/直连）、系统代理、TUN、LAN、TPROXY/REDIRECT | “让整台电脑的流量走代理” |
| 观测 | 实时上下行速率、连接列表与关闭、组测速、节点诊断（TCP 延迟/出口 IP）、命中解释、核心日志（ROUTE 级别）、TUI 日志、任务进度 | “哪里坏了？” |
| 配置 | 可视化条目编辑器（撤销/重做、搜索、折叠、校验保存、热应用）、导入 TOML / Mihomo YAML / 分享链接、外部编辑器、配置复制与切换 | “加个节点/规则，不想手写 TOML” |

### 1.2 用户与场景

| 用户 | 高频场景 | 低频场景 |
|---|---|---|
| 日常使用者（多数） | 开/关代理、切模式、切节点、测速、看是否连通 | 导入订阅、开 TUN |
| 进阶用户 | 写规则、查命中原因、看连接、管理多个订阅与组 | 多实例、绑定、外部编辑器 |
| 运维/开发者 | 日志（ROUTE）、诊断、多窗口监控、无头服务器 | 共享规则核心、自定义目录 |

结论：**高频操作集中在“一个当前配置”的运行时控制**；实例/绑定/路径这类结构性操作是低频的，却在现有界面中占据首屏。

### 1.3 现有设计的主要问题（有代码依据）

1. **对象模型暴露实现细节**。用户必须理解 Proxy Core 与 Rule Core 两类实例（`protocol::Kind`），用 Tab 在两张实例列表间切换，再用 `b` 配置启动绑定（`Action::BindStart`），并手动让 `rule_socket` 与规则 `socket` 一致。用户心智里只有“一套配置”。
2. **运行时页面依赖隐式选择**。仪表盘、代理、连接页的数据取决于“在配置页选中的那个正在运行的代理实例”（`Ui::runtime_instance`），切走选择后数据源随之改变，没有显式的“当前配置”。
3. **键位语义不一致**。`d` 在实例页删除、在连接页关闭连接、在编辑器删除条目；`t` 在代理页是节点诊断、在组列表是测速、在规则实例是命中查询；`r` 是完整重启而 `R` 是热重载（更安全、更常用的操作反而更难按）；`u` 只在编辑器中是撤销。帮助文本（`help.rs`）需要按页面维护大段手写字符串。
4. **Tools 页是杂物间**。日志、诊断、订阅更新、规则查询与所属对象分离。
5. **任务状态在前端**。后台任务（`ui/background.rs`）存于 UI 进程，多窗口（F8）与重开 TUI 后看不到彼此的进度。
6. **IPC 回复弱类型**。`Reply { rows, text }` 用 `text` 承载 JSON（`StoragePaths`、`InstanceDetails` 等），新增能力需要 `*_supported` 标志位做兼容判断；状态靠 500 ms 轮询 + 多条 Watch 连接。
7. **前端与守护进程同居一个 crate**。`manager.rs`（约 2900 行）与 UI 编在一起，编辑器模型（`editor.rs` 约 5700 行，包含字段 Spec、TOML 读写、撤销栈、渲染与按键）无法被 GUI 复用。

## 2. 设计原则

1. **一个对象，一个当前**：用户操作的是“配置档（Profile）”，界面总有一个明确的“当前配置档”。
2. **高频在上，结构在下**：连接开关、模式、节点切换一步可达；实例、绑定、路径收进配置档详情的“高级”区。
3. **同一语义，两种表现**：所有操作定义为命令（Command），TUI 键位、GUI 按钮/菜单、命令面板、帮助文本均由同一份命令注册表生成。
4. **安全默认**：可逆操作直接执行并提供撤销；不可逆或影响系统网络的操作（停止全部、开启 TUN、删除配置档）才确认。热重载优先于重启。
5. **状态可见，原因可查**：每个异常状态都附带“为什么”和“下一步”入口（日志、诊断、修复动作）。
6. **前端无状态、守护进程有状态**：任务、运行时、日志由 manager 持有，前端随开随关、多开一致。

## 3. 统一的对象模型与操作语义

### 3.1 对象

```text
配置档 Profile ── 用户可见的唯一顶层对象
 ├─ 代理端    = 1 个 Proxy 实例（必有）
 ├─ 路由引擎  = 0..1 个 Rule 实例（独立模式为 0；可被多个配置档共享）
 ├─ 运行时    = 模式 / 代理组选择 / 系统代理 / TUN / LAN（manager 私有状态，不写配置）
 └─ 来源      = 订阅、导入记录
```

- 底层仍是现有的 Proxy/Rule 实例与 `instances.toml`，Profile 是 manager 维护的聚合视图：`Profile { name, proxy, rule: Option<String> }`，由现有启动绑定 + `rule_socket` 自动关联推导，迁移零成本。
- **当前配置档（Active Profile）**：全局唯一，manager 持久化。概览、代理、连接、规则、日志页默认都作用于它。切换当前配置档不会自动停止其他配置档。
- 共享路由引擎：编辑规则时若该 Rule 实例被多个配置档引用，顶部提示“影响 N 个配置档”。

### 3.2 统一动词

| 动词 | 含义 | TUI | GUI | 确认 |
|---|---|---|---|---|
| 连接 / 断开 | 启动/停止当前配置档（含依赖的路由引擎，回滚失败的部分） | `c`；概览与配置档列表中也可用 `Space` | 顶栏大开关 | 否 |
| 应用 | 热重载（原 `R`） | `r` | “应用”按钮（有未应用改动时出现） | 否 |
| 重启 | 完整重启（原 `r`） | `R` | 菜单项 | 否 |
| 打开 | 进入详情/成员列表 | `Enter` | 单击/双击 | — |
| 选择 | 在组内切换成员、勾选 | `Enter`/`Space` | 单击 | 否 |
| 新建 | 节点/规则/组/订阅/配置档 | `n` | “＋”按钮 | — |
| 编辑 | 打开表单 | `e` | 单击字段 | — |
| 删除 | 编辑器内删除条目（可撤销） | `d` | 行菜单 / Delete | 否（可撤销） |
| 移除 | 删除配置档注册（保留文件） | `d` 于配置档列表 | 菜单 | 是 |
| 关闭连接 | 关闭单个/全部连接 | `x` / `X` | 行按钮 / “全部关闭” | 全部时是 |
| 测试 | 当前上下文的检测：组测速、节点诊断、路由命中 | `t` | “测试”按钮 | 否 |
| 搜索/筛选 | 当前列表 | `/` | 搜索框（`Ctrl-F`） | — |
| 撤销/重做 | 编辑草稿 | `u`/`Ctrl-Z`、`Ctrl-Y` | `Ctrl-Z`/`Ctrl-Y` | — |
| 保存 | 校验并保存，运行中自动热应用 | `Ctrl-S` | “保存并应用” | 否 |

变更说明：`r`/`R` 互换（热重载更常用且安全）；`d` 不再用于关闭连接（改 `x`），消除“删除 vs 关闭”冲突；`t` 统一为“测试当前对象”，具体做什么由上下文决定并在提示行写明。

### 3.3 命令注册表（两端共享的单一来源）

每个命令是一条静态描述，TUI 与 GUI 都从这里取标签、快捷键、可用性和帮助：

```rust
pub struct CommandSpec {
    pub id: CommandId,            // 如 Connect, SetMode(Mode), TestGroup …
    pub label: &'static str,      // i18n key
    pub key: Option<KeyChord>,    // TUI 默认键位；GUI 用作快捷键提示
    pub scope: Scope,             // Global / Overview / Proxies / Editor …
    pub danger: Danger,           // None / Confirm / Elevation
    pub enabled: fn(&AppState) -> Availability, // Ok | Disabled(原因)
}
```

- **帮助页、底部提示、GUI 工具提示、右键菜单、命令面板**都由注册表生成，不再手写 `help.rs` 的三语长文。
- `Disabled(原因)` 在两端都显示（TUI 灰显并在提示行说明，GUI tooltip），取代“按了没反应”。
- 命令面板（TUI `:` / `Ctrl-K`，GUI `Ctrl-K`）按名称模糊搜索全部可用命令，是低频操作的统一入口，替代 Tools 页。

完整命令清单见附录 A。

## 4. 信息架构

两端共享同一套页面结构与编号：

| # | 页面 | 内容 | 取代现有 |
|---|---|---|---|
| 1 | 概览 Overview | 连接状态、出口节点、模式、接管开关、流量趋势、告警 | 仪表盘 |
| 2 | 代理 Proxies | 代理组 → 成员、测速、节点诊断（出口 IP）、订阅更新 | 代理页 + Tools 中的诊断/订阅 |
| 3 | 连接 Connections | 活动连接、筛选、关闭、详情（规则命中） | 连接页 |
| 4 | 规则 Rules | 规则列表（只读浏览 + 跳转编辑）、路由测试 | Tools 中的规则查询 + 规则编辑入口 |
| 5 | 日志 Logs | 核心日志（当前配置档的 proxy / rule 切换）、TUI/manager 日志 | L、F7、Tools 中的日志 |
| 6 | 配置档 Profiles | 配置档列表、创建/导入、编辑器、高级（实例、绑定、路径） | 配置页（实例列表）+ 编辑器 |
| — | 任务中心 | 全局抽屉/浮层：进行中与最近任务 | F6 任务详情 |
| — | 设置 Settings | 语言、主题、目录、日志保留、manager 状态与重启 | 分散的命令行参数说明 |

导航模型：

```text
全局层：  顶栏（当前配置档 ▾ · 连接开关 · 模式 · 速率）  +  页面导航 1–6  +  状态栏（任务）
页面层：  列表 ⇄ 详情（右侧 Inspector / TUI 右栏）
编辑层：  配置档编辑器（左分区导航 + 右表单），只能从“配置档”或其他页的“编辑…”进入
浮层：    命令面板、确认、输入、帮助、任务中心（Esc 一律关闭最上层）
```

规则：**Esc 永远只后退一层**；任何页面都可用数字键/侧栏直接离开；编辑器离开时草稿保留在会话中（与现状一致），不弹“放弃修改”，只有显式“放弃”才丢弃。

## 5. 架构与 IPC 调整

### 5.1 crate 划分

```text
astra-manager   (新)  守护进程：实例、配置档、运行时代理、任务、日志、提权。从 astra-tui/src/manager*.rs 抽出
astra-client    (新)  manager IPC 客户端：类型化请求、事件流、重连、版本协商（取代 protocol.rs 的 call/subscribe）
astra-app       (新)  前端无关的应用层：AppState、命令注册表、可用性规则、视图模型、
                      配置文档模型（字段 Schema、toml_edit 读写、撤销栈、校验提示）、导入、日志缓冲、i18n
astra-tui             ratatui 渲染 + 键位映射，只依赖 astra-app / astra-client
astra-gui       (新)  egui 渲染 + 鼠标/快捷键映射，只依赖 astra-app / astra-client
```

依赖方向：`astra-tui`、`astra-gui` → `astra-app` → `astra-client` → `astra-ipc`；`astra-manager` → `astra-ipc`、`astra-convert`。前端不得依赖 `astra-manager`。将此约束加入 `scripts/check_architecture.py`。

可执行文件兼容：`astra-tui --manager` 保留为 `astra-manager` 的别名入口（同一份库代码），打包脚本新增 `astra-manager` 与 `astra-gui`。前端启动时若 manager 未运行，按现有逻辑拉起；GUI 与 TUI 可同时连接同一 manager。

**编辑器拆分是关键**：`editor.rs` 的 `Spec`/`Type`/`FlatRow`、TOML 路径读写、引用重命名、撤销栈与校验移入 `astra-app::document`，以“文档 + 字段树 + 操作”形式暴露；TUI/GUI 只负责把字段树画成列表或表单。这样两端的字段、默认值、必填、候选项与引用保护完全一致。

### 5.2 管理 IPC v2

保留现有帧格式（bincode + 长度帧）与本地权限模型，`API_VERSION` 递增。

**(1) 类型化回复**，替代 `Reply { rows, text }` 与 `*_supported` 标志：

```rust
pub enum Request {
    Hello { client: ClientInfo },                 // 返回 ServerInfo { version, capabilities: BTreeSet<Capability> }
    Query(Query),                                 // 只读
    Command { id: Uuid, command: ManagerCommand },// 有副作用，返回 TaskId，进度走事件流
    Subscribe(Vec<Topic>),                        // 独占连接，返回事件流
}
pub enum Query { Profiles, Profile(String), Document(String), Paths, NodeTags(String), SubscriptionNodes(String) }
pub enum ManagerCommand {
    CreateProfile { name: String, source: ProfileSource, routing: Routing },
    Connect(String), Disconnect(String), Apply(String), Restart(String),
    SetActive(String),
    SaveDocument { profile: String, part: Part, base_digest: Digest, text: String },
    Runtime { profile: String, command: runtime::Command },
    UpdateSubscriptions(String),
    Diagnose { profile: String, targets: Vec<String> },
    ExplainRoute { profile: String, request: RouteRequest },
    SetLogLevel { instance: String, level: LogLevel },
    RemoveProfile(String), StopAll,
    Advanced(InstanceCommand),                    // 现有实例级操作：Add/SetConfig/Clone/BindStart …
}
```

能力用 `capabilities` 集合协商，前端据此决定命令可用性（`Availability::Disabled("需要更新后台服务")`），不再在每种详情里塞布尔字段。

**(2) 单一事件流**，替代 `WatchList` + 每实例 `WatchRuntime` + 500 ms 轮询：

```rust
pub enum Topic { Profiles, Runtime(String), Tasks, Logs { instance: String, cursor: Option<LogCursor> } }
pub enum Event {
    Profiles(Vec<ProfileView>),                  // 变化时推送全量（数量小）
    ProfileState { name: String, state: State },
    Runtime { profile: String, snapshot: runtime::Snapshot },   // manager 端节流 500 ms
    Task(TaskEvent),                             // Started / Stage{done,total,detail} / Finished{ok|err}
    Log { instance: String, chunk: LogChunk },
    Notice(Notice),                              // 需要用户处理的异常：端口占用、配置被外部修改、需要提权…
}
```

**(3) 任务归 manager**：`ui/background.rs` 的任务记录（最近 32 个、每个 128 阶段）迁到 manager，所有前端看到同一份任务中心；断开前端不取消任务，显式“取消”命令才取消（诊断等可取消任务）。

**(4) 配置档操作在 manager 内完成依赖处理**：`Connect` 内部复用现有绑定启动与回滚逻辑；`CreateProfile` 自动分配不冲突的规则 socket 与监听端口（现在需要用户手工保证），`routing = Standalone` 时不创建 Rule 实例。

**(5) 保存冲突检测**沿用现有“原文比对”，改为传摘要 `base_digest`，减少大配置往返。

兼容策略：manager 在过渡期同时接受 v1 请求（旧 TUI 继续工作）；新前端遇到 v1 manager 时提示“后台服务版本较旧，[重启后台服务]”，按钮执行现有 `--shutdown` + 重新拉起流程（会先正常停止 core，需确认）。

### 5.3 前端内部结构（两端相同）

```text
事件流 / 查询结果 ──▶ AppState（纯数据，可序列化为会话）
用户输入 ──▶ 输入映射（TUI 键位 / GUI 控件）──▶ CommandId
CommandId ──▶ astra-app::dispatch(state, cmd) ──▶ 本地状态变更 和/或 ManagerCommand
AppState ──▶ 视图模型（ViewModel，按页面）──▶ 渲染（ratatui / egui）
```

`AppState` 与 dispatch 可在无终端、无窗口的情况下单元测试；现有 `ui.rs` 中大量基于按键的测试改写为基于 CommandId 的测试，渲染测试只保留布局断言。

## 6. TUI 设计

定位：键盘优先、信息密集、适合 SSH 与常驻监控。最小 80×24，推荐 120×32；宽度 ≥ 140 时启用右侧详情栏。

### 6.1 视觉风格

- 不使用大面积色块与重边框卡片；以**留白分隔 + 单线标题**组织信息，边框只用于浮层。
- 颜色只表达语义：绿=运行/可用，黄=警告/未应用/测速慢，红=错误/失败/拒绝，青=当前选中与焦点，灰=次要信息与默认值。其余文字使用终端前景色，保证浅色终端可读。
- 延迟三档：<150 ms 绿，<400 ms 黄，≥400 ms 或失败红；未测为 `—`。
- 数字右对齐、单位固定宽度（`12.4 MB/s`），表格列宽稳定，刷新时不抖动。
- 支持 `NO_COLOR`：去色后以符号区分状态（`●` 运行、`○` 停止、`!` 错误、`~` 进行中）。

### 6.2 全局布局

```text
┌ Astra ─ home ▾ ● 已连接 2h13m ─ 规则 ─ 系统代理 ✓ TUN ✗ LAN ✗ ───── ↑ 1.2 MB/s ↓ 8.4 MB/s ┐
│ 1 概览  2 代理  3 连接  4 规则  5 日志  6 配置档                                           │
├────────────────────────────────────────────────────────────────────────────────────────────┤
│                                                                                            │
│                                  页面内容                                                  │
│                                                                                            │
├────────────────────────────────────────────────────────────────────────────────────────────┤
│ ~ 测速 PROXY 3/12 · 2.1s                                         Space 连接 m 模式 ? 帮助  │
└────────────────────────────────────────────────────────────────────────────────────────────┘
```

- 第 1 行顶栏：当前配置档、状态与时长、模式、接管开关、速率。`p` 打开配置档切换器（模糊搜索）。
- 第 2 行导航：数字键直达；窄于 100 列时只显示编号与当前页名。
- 底部状态栏：左侧为最新任务（点击或 `F6` 展开任务中心），右侧为**当前上下文最常用的 3–5 个命令**（由注册表按 scope 与可用性生成）。
- 全局键：`1–6` 页面，`p` 切换配置档，`c` 连接开关（概览页也可按 `Space`），`m` 轮换模式，`S`/`T`/`A` 接管开关，`:`/`Ctrl-K` 命令面板，`?` 帮助，`F6` 任务中心，`Esc` 后退，`q` 退出界面（核心保持运行），`Ctrl-Q` 停止全部（确认）。
- 键位优先级：输入框/字段编辑 > 浮层 > 页面键 > 全局键。编辑器与日志页有自己的单字母键（如编辑器 `r` 重命名、日志 `Space` 暂停），在这两处全局单字母键（`c` `m` `r` `R` `p` `S` `T` `A`）不生效，只保留数字键、功能键和 Ctrl 组合；被屏蔽的全局命令仍可从命令面板执行。注册表在构建期检查同一作用域内无重复键位。
- `F8` 在新窗口打开当前页面（保留现有多窗口能力，实现上改为同一 manager 的另一个前端，不再需要窗口会话文件之外的特殊逻辑）。

## 7. GUI 设计

定位：直观、视觉层次清晰、鼠标与触控板友好，面向日常使用者；进阶功能完整但默认收起。

### 7.1 技术选型

推荐 **egui / eframe**：

- 纯 Rust、单二进制，与 TUI 共享 `astra-app` 无需跨语言绑定，维护成本最低；
- 即时模式与“AppState → ViewModel → 渲染”结构天然契合，事件流更新后直接重绘；
- Windows/macOS/Linux 一致；中文需内嵌字体（Noto Sans SC 子集，约 4–6 MB，或运行时加载系统字体并回退）。

备选：Slint（声明式、观感更原生，但 UI 描述在 `.slint` 中，复杂表单的动态字段树需要较多桥接代码）；Tauri（Web 技术栈，视觉上限最高，但引入 TS 前端与第二套状态，违背“易于维护”）。

系统托盘（`tray-icon` crate）作为 GUI 的组成部分：连接开关、模式、当前出口、打开主窗口、退出界面。

### 7.2 视觉风格

- 基调：中性灰背景 + 单一强调色（靛蓝），语义色与 TUI 一致（绿/黄/红）。浅色与深色两套主题，跟随系统。
- 设计令牌（`astra-gui/src/theme.rs` 一处定义）：

| 令牌 | 浅色 | 深色 | 用途 |
|---|---|---|---|
| `bg` | #F6F7F9 | #15171C | 窗口背景 |
| `surface` | #FFFFFF | #1D2027 | 卡片、面板 |
| `border` | #E3E6EB | #2C3039 | 分隔线 |
| `text` / `text-muted` | #1A1D23 / #6B7280 | #E7E9EE / #8B93A1 | 文本 |
| `accent` | #4F5BD5 | #7C86F0 | 焦点、主按钮、选中 |
| `ok` / `warn` / `err` | #1F9D55 / #C98A0B / #D64545 | #3CCB7F / #E5B33E / #F06A6A | 状态 |

- 字号：标题 20、区块标题 15（半粗）、正文 13、辅助 12；数字使用等宽数字（tabular）。
- 间距 4 的倍数；卡片圆角 8；阴影只用于浮层。
- 动效克制：开关与抽屉 150 ms，测速结果出现时数值淡入；尊重系统“减少动态效果”。

### 7.3 窗口布局

│  Astra   │  [home ▾]   ( ● 已连接 )   [规则|全局|直连]       ↑1.2MB/s ↓8.4MB/s │
│          ├───────────────────────────────────────────────────────────────────┤

│ ▤ 配置档 │                                                     │             │

- 侧栏宽 200，可收起为图标栏（64）；窗口宽 < 900 时自动收起。
- 顶栏三件套：配置档选择器、连接主开关（最大的可点击元素）、模式分段控件；与 TUI 顶栏一一对应。
- 右侧详情抽屉（360 宽）：选中节点、连接、规则、任务时打开，取代多级弹窗。

- `Ctrl-K` 命令面板（与 TUI 同源），`Ctrl-1…6` 切页，`Ctrl-F` 页内搜索，`Ctrl-S` 保存，`Esc` 关闭抽屉/面板。

### 7.4 页面

**概览**：

- 主卡片：大号连接状态 + 时长 + 出口链路（PROXY ▸ 自动-香港 ▸ hk-02，带延迟徽标与出口 IP），右侧“断开 / 应用改动”按钮。
- 接管卡片三张并排：系统代理、TUN、LAN。每张卡写明一句作用（“让浏览器等遵循系统代理的应用走 Astra”），开关旁显示需要的权限（盾牌图标 = 需要管理员，开启时触发 UAC）；不支持的平台显示禁用原因。
- 流量面板：60 秒上下行面积图 + 累计与活动连接数；点击跳转连接页。
- 提醒列表：与 TUI 提醒区相同的数据，每条带按钮。

**代理**：

- 组以卡片网格展示：卡头为组名、模式徽标、当前选择、测速按钮；卡体为成员“药丸”，颜色表示延迟档，当前项加强调描边。点击成员即切换（自动组卡体显示“自动选择”并禁用点击）。
- 顶部工具条：搜索、排序、“全部测速”、“更新订阅”。
- 选中节点打开详情抽屉：协议/服务器摘要、诊断结果（TCP 延迟、连通性、出口 IP）、“诊断”按钮、“在编辑器中打开”。

**连接**：虚拟化表格（列同 TUI，可调列宽），顶部搜索与“暂停刷新”“全部关闭”；行悬停出现关闭按钮；点击行打开抽屉，含“解释路由”结果。

**规则**：顶部路由测试输入框 + 结果卡片（命中路径以面包屑展示：`#12 GEOSITE(cn) ▸ 展开 #3401 ▸ DIRECT`）；下方规则分段列表，命中项高亮；行内“编辑”跳转编辑器。

**日志**：工具条（来源、显示级别、记录级别、搜索、过滤、换行、暂停）+ 等宽日志区；级别着色；ROUTE 行可点击打开结构化详情。

**配置档**：卡片列表（名称、状态、模式、出口、监听），“新建/导入”主按钮打开向导对话框（与 TUI 向导字段一致，支持拖放文件）。打开配置档进入编辑器：

- 左侧分区导航（与 TUI 左栏同源），右侧为表单：每个字段一行“标签 / 控件 / 说明”，布尔用开关、枚举用下拉（带搜索）、引用用可搜索选择器、字符串列表用标签输入、密码带显示按钮；未设置的可选字段以占位符显示默认值；修改过的字段左侧有强调色竖条。
- 节点、规则、代理组为可拖拽排序的列表，点击展开为表单；规则拖拽排序时提示“规则按顺序匹配”。
- 底部固定保存条：未保存数量、错误数量、“放弃”“保存并应用”。
- 高级分区：配置文件路径（文件选择器）、复制、启动绑定（多选列表）、日志级别、外部编辑器打开。

**设置**：语言、主题、侧栏、托盘行为（关闭窗口时最小化到托盘 / 退出界面）、目录（只读展示，附“在文件管理器中打开”）、后台服务（版本、PID、重启后台服务、停止全部）。

## 8. 主要流程（优化前后）

### 8.1 首次使用：从订阅到上网

| 现在 | 重设计 |
|---|---|
| 1. Tab 到 Rule Core，`n` 建规则实例，编辑并保存 | 1. 首次启动直接进入“新建配置档”向导 |
| 2. `s` 启动规则实例 | 2. 粘贴订阅链接，保持“规则模式”，回车 |
| 3. Tab 回 Proxy Core，`n` 建代理实例 | 3. manager 创建代理与路由引擎（自动分配端口与 socket）、拉取订阅、设为当前 |
| 4. 编辑器里找到订阅分区添加链接，确认 `rule_socket` | 4. 概览页按 `Space` / 点击“连接” |
| 5. `Ctrl-S`，`Ctrl-R` 更新订阅，`s` 启动 | 5. 需要全局接管时按 `S` 或打开系统代理卡片 |
| 6. 回仪表盘按 `S` |  |

### 8.2 切换节点

现在：配置页选中运行实例 → `2` → 选组 → `Enter` → 选成员 → `Enter`。
重设计：`2` → 选组 → `Enter` 成员 → `Enter`（不依赖配置页的选择）；GUI 点一次成员药丸；托盘子菜单也可切换 PROXY 组。

### 8.3 “某网站为什么没走代理”

现在：Tools → 规则查询（需选中运行中的规则实例）→ 输入；或开 ROUTE 日志自己找。
重设计：连接页选中该连接 → `Enter` → 详情中即有命中路径；或规则页输入域名，命中规则高亮，`e` 直接跳到编辑位置修改，`Ctrl-S` 保存即生效。

### 8.4 开启 TUN（Windows 非管理员）

现在：按 `T`，UAC 弹出，结果在操作状态框中。
重设计：开关旁预先标注“需要管理员”；开启时任务中心显示“请求管理员权限 → 重启代理端 → 已启用”的阶段；取消 UAC 时开关回弹并在提醒区显示原因与“重试”按钮。

### 8.5 编辑与应用配置

保存（`Ctrl-S`）= 校验 + 写入 + 运行中自动热应用，与现在一致；新增：保存条显示错误数量并可跳转；外部修改导致冲突时，提供“查看差异 / 以磁盘为准重新载入 / 导入为草稿”三选一，而不是只报错。

### 8.6 故障排查

概览提醒区汇总：核心异常退出（附日志末行）、端口占用、配置未应用、订阅更新失败、后台服务版本过旧。每条都有一键动作（打开日志定位到时间点、编辑监听端口、应用、重试更新、重启后台服务）。

### 保持不变的契约

- 配置文件格式与字段、`instances.toml`、运行时 `overrides` 缓存、日志文件位置与格式。
- Core 控制 IPC（`astra_ipc::control`）与路由 IPC 不变；变化只发生在“前端 ↔ manager”这一层。
- 命令行入口：`--state-dir`、`--config-dir`、`--bin-dir`、`--lang`、`--shutdown`、`--manager`、`--view`（映射到新页面名：`dashboard→overview`、`tools` 移除并给出提示）。
- 草稿与会话恢复语义：未保存草稿不写配置、崩溃后可恢复。

### 风险与对策

| 风险 | 对策 |
|---|---|
| `editor.rs` 迁移量大、易引入回归 | P1 只搬运不改行为，先用现有测试守住，再做 UI 侧改动 |
| Profile 聚合与复杂绑定（一个规则被多个代理共享、代理未绑定）不一致 | Profile 由现有绑定规则推导而非新存储；无法归属的实例在“配置档 ▸ 高级 ▸ 未归属实例”中列出，不隐藏 |
| `r`/`R` 互换造成误操作 | 两者都不破坏数据；过渡版本中按 `r` 首次显示一次说明 |
| GUI 中文字体体积 | 优先加载系统字体，失败再用内嵌子集 |
| 事件流引入背压问题 | Runtime 事件在 manager 端合并节流，只保留最新快照；日志沿用现有续传游标 |

## 10. 服务端控制台

`astra-server-tui` 当前只有状态、停止、重载与日志（`astra_server_api::Action`）。建议在客户端 P3 后复用同一视觉语言与 `astra-app` 中的通用组件（状态栏、日志查看器、命令面板），页面为：概览（监听、活动/接受/拒绝、流量）、用户与配额、日志。服务端多部署在无图形环境，不提供 GUI。
