# Rust TUI 管理

`astra-tui` 使用 Rust、Ratatui 和 Crossterm，运行时不需要 Python。支持 Linux/macOS 的 Unix Domain Socket。

## 启动

统一编译、测试并打包三个原生程序可运行 `./scripts/build.sh`，输出到 `dist/`；选项见 [构建与打包说明](INSTALL.md)。

```sh
cargo build --workspace
./target/debug/astra-tui
```

发行构建使用 `cargo build --release --workspace`，然后运行 `./target/release/astra-tui`。新打包脚本包含 `bin/astra-tui`，解压后可直接运行。core 可执行文件默认与 TUI 在同一目录，可通过 `--bin-dir DIR` 指定。

首次启动自动创建 Rust 后台管理服务；再次启动连接已有服务。默认状态目录为 `~/.astra/tui`，可通过 `--state-dir DIR` 指定一个较短的绝对路径。该目录持久化实例注册表、管理 socket、日志和 `ui-session.json` 操作状态，权限为 0700，socket 与操作状态文件为 0600。

首次列表为空。按 n 输入实例名称即可创建实例，自动生成并绑定 `状态目录/configs/<实例名>.toml`，随后进入条目编辑器，不再要求先输入配置路径。每个新实例默认使用自己的配置文件，绑定关系保存在实例注册表中，后续编辑、校验、启动均使用这份配置，重新打开 TUI 后无需再次选择。删除实例时保留配置；重新创建同名实例会复用这份配置。

首个默认 Rule Core 使用状态目录内的 `rule.r`，后续规则实例使用各自的 socket。新 Proxy Core 默认连接首个已注册 Rule Core；若尚无 Rule Core，则预设连接 `rule.r`，可稍后创建首个 Rule Core。多个 Proxy Core 的监听端口仍需分别配置。

使用已有配置时，创建实例后按 c 选择项目内或其他位置的配置文件，校验成功后更新并持久化绑定关系。路径不存在时创建对应默认配置并进入编辑。已有文件不会被默认模板覆盖；显式选择同一份外部配置会共享其修改，默认生成的配置彼此独立。

配置路径支持空格和相对路径（相对于开始这项操作时的目录），不做 shell 展开，请勿输入 `~`。恢复之前未完成的输入步骤时，继续使用原操作的目录解析相对路径。

规则模式先启动 Rule Core，再启动 Proxy Core。独立模式在代理基础设置将“独立代理模式（无需 Rule Core）”设为 true；单节点自动选用，多节点填写“独立模式出站标签”，然后只启动 Proxy Core。它们独立管理；停止 Rule Core 不会自动停止 Proxy Core，新请求仍遵循既有的缓存和失败关闭策略。

## 键盘操作

| 按键 | 功能 |
|---|---|
| Tab | 切换 Proxy Core / Rule Core |
| ↑ / ↓ | 选择实例 |
| n | 输入唯一名称，创建实例并自动生成、绑定独立配置 |
| s / x / r / R | 启动 / 停止 / 完整重启 / 热重载选中实例 |
| d | 删除已停止实例的注册信息，保留配置文件；输入 yes 确认 |
| c | 选择另一个配置文件，校验后关联；运行中热应用，失败保留旧选择 |
| y | 复制当前配置到同目录的新文件，不覆盖已有文件 |
| e | 打开可视化条目编辑器 |
| v | 调用对应 core 的 `--check` 校验配置 |
| l | 打开实时日志，支持搜索、过滤、级别选择和历史滚动 |
| q / Ctrl-C | 断开界面并记住操作状态，后台管理服务和 core 继续运行；编辑器中用 Ctrl-C 保留草稿并退出 |
| Q | 确认后先停止所有 Proxy Core，再停止 Rule Core 和管理服务 |

选择外部配置的输入框中按 Esc 可取消。旧会话中尚未完成的实例配置路径输入仍可继续。建议至少使用 100×24 的终端。

## 实时日志

日志通过独立的管理 IPC 连接持续推送，不需要手动刷新，也不会占用实例管理请求连接。初次打开读取文件末尾最多 64 KiB，再跟随新增内容；文件尚未生成时保持等待。暂停跟随或滚动历史只停止自动滚动，仍继续接收日志。

| 按键 | 日志页行为 |
|---|---|
| / | 输入搜索词，Enter 应用并高亮匹配行；n / N 跳转到下一条 / 上一条匹配 |
| f | 输入关键词过滤，只显示包含关键词的行，支持中文，不区分大小写 |
| l | 选择显示级别：全部、TRACE、DEBUG、INFO、WARN、ERROR；选择级别显示该级别及以上，未标注级别的 stderr 仍保留 |
| L | 选择 core 实际记录级别，通过控制 IPC 立即生效，无需重启；设置与实例一起持久化，停止中的实例在下次启动时生效 |
| 空格 | 暂停/恢复跟随最新日志 |
| ↑ / ↓、PageUp / PageDown | 滚动历史；Home 最早缓冲行，End 恢复跟随最新 |
| ← / → | 水平滚动长日志行 |
| Backspace | 清除搜索词、关键词过滤和显示级别过滤 |
| r | 重新连接，按已接收位置续传 |
| Esc | 关闭当前输入窗口；再次按 Esc 返回实例列表 |

显示过滤与实际记录级别独立：默认 core 记录 INFO 及以上，需查看 DEBUG 时使用大写 L 提高实际记录详细度，再用小写 l 选择显示范围。调整记录级别保持 core PID 与已有会话不变。独立运行的 core 仍支持 `RUST_LOG`；受管理实例使用保存的实例级别设置。

搜索与过滤作用于当前缓冲及随后到达的日志；每实例界面最多保留 5000 行 / 2 MiB，超限淘汰最早记录，文件内容不受影响。单行最多显示 64 KiB，超长行会标记截断。日志文件仍追加写入，不自动轮转；能够识别更换文件与常见截断后继续跟随。过滤、搜索词、未完成输入、跟随开关按实例记忆，重新打开日志页或 TUI 后恢复。

断线时保留已收日志、过滤条件和续传位置，按 c 重连，按 b 停止本次订阅并保留缓冲，可按 r 再连接。订阅数最多 16 个；关闭日志页或退出 TUI 会释放订阅。历史完整日志位于状态目录的 `<实例名>.log`。

## 可视化条目编辑器

编辑器将配置平铺在同一页，不需要手写 TOML，也不再进入多级菜单。基础设置和全部规则字段直接显示。只有出站节点可以折叠：展开一个节点后，其节点信息、协议、TLS/REALITY、传输和自定义请求头全部在下方平铺，分组标题只起标识作用。原有 TOML 注释与未修改字段会保留。

| 按键 | 编辑器行为 |
|---|---|
| ↑ / ↓、Home / End、PageUp / PageDown | 在同一页选择字段或条目；翻页每次移动 10 行 |
| Enter | 编辑字段；在节点标题上展开/收起节点；在 TLS 标题上启用/关闭 TLS |
| → | 编辑字段或展开节点，不进入子页面 |
| Esc / ← | 当前字段中取消输入；在展开节点内收起该节点；Esc 再次返回实例列表，未保存修改需确认 |
| n | Rule Core 新增规则，Proxy Core 新增节点；选中请求头行时新增请求头；也可直接选择“新增请求头”并按 Enter |
| d | 删除所选条目、可选字段或分组，y 确认、n / Esc 取消；必填字段受保护 |
| K / J | 将当前标题或字段所属的规则/节点上移 / 下移 |
| Ctrl-S | 提交正在输入的字段，调用对应 core 校验，再保存完整配置 |
| Ctrl-C | 保留当前表单、条目位置和未提交的字段输入，退出界面 |

字段编辑窗口中，↑ / ↓ 可选择协议、匹配类型或传输方式等枚举值；文本、路径、凭据和数字直接输入，不需要 TOML 引号。打开字段时选中当前值，直接输入或粘贴会替换该值；方向键可移动光标，Ctrl-U 清空，Enter 确认、Esc 取消。密码、UUID 和认证请求头默认隐藏，F2 显示/隐藏。端口、连接数、超时等数字会即时检查类型与范围；错误继续使用 c 恢复输入，b 结束本次字段编辑。

未设置的可选参数会显示 core 默认值，未填必填项会标记提示。监听地址留空表示禁用该入站。可选字段可清空或删除以恢复默认行为；在分组标题上按 d 可删除该组参数，在规则/节点标题上按 d 删除整条规则/节点。TLS 关闭时参数仍平铺显示，直接填写 TLS 字段也会启用 TLS，并根据节点服务器补上默认服务器名。新增节点支持 SOCKS5、HTTP CONNECT、VLESS、VMess、Shadowsocks、Trojan、Hysteria2、TUIC 与旧版 TLS 节点，初始服务器和凭据为待替换的示例值。

切换节点类型会重置该节点的专用字段并保留标签；切换原生协议会保留可复用的服务器、端口、凭据与 TLS 参数，重置不适用的协议字段，请在保存前检查。规则严格按列表顺序匹配。Ctrl-S 保存时会对运行中的 core 热应用；失败恢复原文件。`R` 手动热重载，`r` 仍为完整重启。

关闭编辑器时，尚未保存的配置修改需要确认丢弃。节点的展开/收起状态随草稿保存，排序、删除时跟随对应节点。旧多级菜单中的草稿和未完成的字段输入会迁移到单页布局；旧文本编辑器的有效配置草稿也可恢复。格式损坏的 TOML 会保留并提示修复，不会自动覆盖原文件。

## 操作记忆与错误恢复

TUI 记住当前 core 页、两个 core 页分别选中的实例位置、输入步骤和内容、编辑草稿与光标，以及尚未处理的错误。重新打开同一状态目录会恢复这些状态；未保存的草稿只保存在操作状态文件中，不会自动写入运行配置，也不会自动重放启停操作。

遇到不存在或被占用的路径、权限不足、配置校验失败、端口冲突或 IPC 连接失败等可恢复错误时，界面暂停当前步骤并显示完整错误：

| 按键 | 错误界面行为 |
|---|---|
| c | 继续当前操作。输入失败会恢复输入框与原输入，允许修正；保存失败返回原编辑草稿；其他操作按原实例重试 |
| b | 结束当前操作并留在 TUI；不退出应用，不关闭运行中的 core，不丢弃编辑草稿 |
| ↑ / ↓ | 滚动错误详情 |
| Ctrl-C | 记住当前步骤并退出界面，稍后继续 |

若状态文件因权限等原因无法保存，c 会重试保存；b 结束本次状态保存，此次运行仅保留内存中的操作状态。状态文件上限 4 MiB。操作状态包含原始配置草稿，按配置凭据文件保护。

若在启动、重启或校验时发现已注册实例的配置文件被删除，会重新生成对应默认配置并进入编辑，当前启动操作不会继续执行；编辑完成后需手动保存和启动。默认代理仅监听 loopback，默认规则为直连；多实例的端口和规则 socket 仍需在编辑器中分别设置。

配置校验使用同目录临时文件，保留相对 CA/TLS 文件路径的含义。失败时保留原文件和编辑内容；成功时先备份为 `<原文件去扩展名>.toml.bak`，再原子替换原文件，写入权限为 0600。再次保存会更新这份备份。若文件在编辑期间被其他程序改动，拒绝覆盖，需要重新打开。文件大小上限 480 KiB。

界面显示 PID、运行时间、退出状态及 `reload pending`；核心报告实际加载路径与内容摘要。保存和切换配置会对运行中实例热应用，也可按 R 重载。共用同一个配置文件的实例都受文件编辑影响。复制配置后可为不同实例分别选择文件；复制限制在同目录，以避免相对证书路径变化。多实例必须使用不同的监听端口和规则 socket；Proxy Core 的 `rule_socket` 指向所需 Rule Core 的 `socket`，不会自动分配或改写。

## IPC 与生命周期

```text
astra-tui 界面
    │ 版本化 bincode + 长度帧 / manager.sock
    ▼
astra-tui --manager（原生 Rust 后台进程）
    ├─ 实例注册、配置校验/编辑、子进程与日志管理
    ├─ 独立日志连接：FollowLogs，持续推送并支持续传
    ├─ proxy实例.sock → Proxy Core：Status / Stop / Reload / SetLogLevel
    └─ rule实例.sock  → Rule Core：Status / Stop / Reload / SetLogLevel

Proxy Core ── 原有路由 IPC ──> Rule Core
```

管理服务通过 `ASTRA_CONTROL_SOCKET` 为它启动的 core 设置独立的控制 socket。`Stop` 进入 core 原有的停止流程，Proxy Core 停止接受新连接并等待会话结束。默认最多等待 30 秒，随后强制终止；控制 IPC 不可用时也只能强制终止该管理服务直接持有的子进程。不会按保存的 PID 杀进程。路由帧仍限制为 8192 字节，TUI 管理帧限制为 1 MiB。管理操作串行执行，启动、校验或停止期间界面会显示 Working，完成后更新。

退出 TUI 不等于停止代理。可在终端显式停止：

```sh
./target/debug/astra-tui --shutdown
# 使用自定义状态目录时，两边应指定相同目录
./target/debug/astra-tui --state-dir /tmp/my-astra --shutdown
```

`--manager` 可在前台运行管理服务，便于调试或接入服务管理器。它响应 SIGINT/SIGTERM，按代理优先的顺序停止子进程。注册信息跨重启保存，但不会自动重新启动实例。已经由其他启动器运行的 core 不会自动接管。

更新二进制后，需要让后台管理服务也运行新版本。若仍运行旧服务，请先用对应状态目录执行 `astra-tui --shutdown`，再重新打开 TUI；这会先正常停止其管理的 core。

管理进程被 SIGKILL、机器断电等异常打断后，可能留下孤儿 core 或 socket；重启时拒绝覆盖已有 socket。检查 `manager.log`、`<实例名>.log` 和存活进程，确认停止后再清理遗留 socket。日志采用追加写入，当前不做自动轮转，请按需清理已停止实例的日志。

### VLESS Encryption 与证书指纹

VLESS 节点的“协议参数”中增加“VLESS Encryption（完整字符串）”，对应 `outbounds.config.encryption`；填写完整 `mlkem768x25519plus...`，不能填到 cipher 或 flow。

TLS 表单分开显示两个字段：

- “客户端 TLS 指纹”：如 `chrome`，通过选项列表选择，对应 `tls.fingerprint`。
- “服务端证书 SHA-256 指纹”：64 位十六进制，对应 `tls.cert_pin_sha256`。该 pin 替代 CA 验证，不能与自定义 CA 或 REALITY 同时使用。

XHTTP 模式新增 `auto`：普通 TLS 使用 packet-up，REALITY 使用 stream-one。已有配置中的 stream-one 不自动改写，按节点参数自行选择。

旧版表单中若曾把证书哈希填写在“TLS 指纹”一行，需要手动将它移到新的“服务端证书 SHA-256 指纹”，再把“客户端 TLS 指纹”选为节点要求的 `chrome` 等值。更新后用 `target/release/astra-tui` 启动；旧解压包的 TUI 不会自动更新。若后台管理服务仍运行旧二进制，按上文更新管理服务的方法重启。

系统代理、TUN、TPROXY、REDIRECT 分组可在代理编辑器中启用/关闭，路由/服务名称以 TOML 字符串列表编辑。平台要求、系统设置恢复和设备重建边界见 [模式与热重载说明](PROXY_MODES.md)。
