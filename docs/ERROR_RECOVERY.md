# 异常退出与恢复

核心发生关键任务错误、panic 或意外返回时会退出并记录任务及原因，不自动重启。单个连接的协议或网络错误只影响该连接；监听器的暂时错误限速重试。规则服务不可用时仍使用既有路由策略，不增加直连回退。

## 管理器与核心的生命周期

关闭 TUI 或 Web 不会停止后台核心。显式停止实例或停止全部时，先排空代理，再停止规则服务，并尝试停止全部受管服务端和在线更新代际；单个停止错误不会跳过其他实例。

启动中的核心是候选服务，只有身份验证、运行清单持久化及就绪提交成功后才成为已提交服务。候选的启动方退出时，候选自行退出。已提交服务不依赖管理器连接的存活；管理器崩溃或被强杀后，健康核心继续服务。

重新启动同一状态目录的管理器时，会从私有运行清单恢复受管实例，校验进程启动时间、启动 ID、IPC 对端以及已加载配置的路径和摘要。PID 相同不足以接管或终止进程。身份不符或暂时无法验证时保留记录并报告，避免重复启动或误杀。IPC 请求超时只能说明无响应，不能证明进程已经死亡。

Unix IPC 的独占所有权锁用于区分活跃端点与崩溃遗留端点。普通文件、链接及权限或所有权不明的对象不会当作遗留 socket 删除。

## 网络恢复助手与记录

真正持有网络设置的代理核心在修改系统代理或 TUN 资源前，启动同一二进制的恢复助手并完成就绪检查。在线更新模式由网络宿主持有助手，worker 代际不接管它。助手失效会触发核心受控清理和故障退出。

恢复日志保存在运行目录的 `network-recovery/<运行ID>.json`；运行目录可由 `ASTRA_RUNTIME_DIR` 指定。日志按版本和类型记录原值、预期值、资源身份及提交状态。助手诊断输出在相邻的 `.log` 文件。文件为私有文件，不能删除尚未处理完成的记录。

恢复包括系统代理、Astra 添加的接管及绕过路由，以及复用 Windows Wintun 时修改的地址、MTU 和 metric。共享路由的引用随候选配置、当前配置和仍有连接的旧代际保留，避免候选回滚删除旧连接使用的路由。

正常清理与助手恢复由独占锁串行化。助手确认核心死亡后逆序恢复；核心与助手同时退出或机器重启后，下次需要接管网络的启动先处理遗留记录。恢复失败不会覆盖旧记录或继续接管。

只恢复身份可验证、当前值仍符合本次修改的资源。外部修改保留并报告冲突。创建路由后尚未写入成功检查点就被强杀时，单凭相同路由值不能确定归属，记录保留为待处理。界面实例详情显示最近的恢复状态、原因和记录路径；“待恢复”或“冲突”不表示恢复成功。

需要重试时，以原用户及所需权限执行：

```sh
astra-proxy --recover-network /absolute/path/to/network-recovery/<运行ID>.json
```

该命令拒绝恢复仍有活跃所有者的记录。旧版系统代理记录继续使用：

```sh
astra-proxy --restore-system-proxy /absolute/path/to/proxy.system-proxy-state.toml
```

系统代理和 TUN 的持久化开关不会因崩溃被清除。恢复旧设置后，手动启动仍按保存的开关执行。Windows 系统代理监控不覆盖运行期间的外部修改。

## 操作结果与界面恢复

已接受操作的进度写库失败不会取消执行。终态无法持久化时返回 `OutcomeUnknown`，保留原操作 ID；应查询原 ID 的状态，不重新提交写操作。进程重启后，未能确认的操作仍保持不确定，不自动重放。

Web 在发送保存前保存操作 ID。响应体断流、JSON 截断或无效响应均按结果不确定处理；恢复页面后可继续查询原操作。401 在解析响应体前使登录失效。存储不可用时界面降级并提示，恢复动作保留草稿；渲染错误边界提供重新加载入口。

TUI 在系统信号、输入 EOF、输入错误和绘制错误后统一尝试保存草稿并恢复终端。强杀进程无法执行终端收尾。Web 网关停止接受新请求后有界等待已有请求结束。

## 重载期限与锁故障

SIGHUP 重载通过统一 tracing 日志记录接受、完成、拒绝和超过 60 秒期限；控制队列已满时记录明确的跳过原因。60 秒是等待结果的期限，不是取消已经接受的配置事务。超过期限的重载或运行状态修改继续执行原操作，IPC 返回结果不确定并提示先查询状态；不自动重放。纯查询仍可超时取消。

热重载先等待所有提交锁，再连续发布配置和资源；最终发布阶段不含异步等待。取消发生在准备阶段时只回滚候选资源。持久化运行开关使用可回滚检查点；宿主与 worker 的修改确认丢失时记录结果不确定并进入受控清理，不假定回滚成功。

已加载配置身份与运行开关使用不可变原子快照，发布方 panic 不会使后续读取发生锁中毒。选择、活动连接等可重建索引中毒时先取消受影响租约再清理；TUIC 关联表故障关闭受影响会话，防止复用不确定的关联 ID。宿主事务状态中毒进入故障退出；清理路径只取回锁中的资源用于释放，不继续使用不确定状态。

## 管理数据库故障

管理数据库由单独的 SQLite 线程处理。线程 panic 是管理服务的致命故障，Agent 和 Controller 都会停止服务，不会自动重启数据库线程或重放队列中的写操作。已提交核心仍按进程接管策略保留；待完成操作在下次显式启动后保持 `OutcomeUnknown`。普通 SQL 错误会返回给调用者，不等同于线程崩溃。

SQLite 的锁等待明确设为每次最多累计 5 秒，与当前 rusqlite 的既有默认值一致。短暂锁竞争可在期限内等待释放；持续占锁返回错误，不会无限重试。数据库工作线程与异步运行时分离，锁等待不占用 Tokio 工作线程。

数据库损坏或格式无效时拒绝启动，并显示文件路径和 SQLite 原因，不自动修复或重建。非空文件先以只读方式检查 SQLite 文件头；文件头明确无效时，在打开 SQLite 写连接之前拒绝启动，保留数据库及旁边 WAL/SHM 的原始内容。新建、空数据库和有效的活跃 WAL 不会被此检查拒绝。更深层的损坏仍由 SQLite 检测：失败初始化禁用关闭时自动 checkpoint，但 SQLite 打开过程中仍可能重建 SHM 索引，不能保证所有损坏情况的 SHM 字节不变。先停止所有使用该状态目录的程序，将 `management.sqlite`（Controller 为 `controller.sqlite`）及仍存在的 `-wal`、`-shm` 文件作为一组复制保留，再在副本上检查或恢复经过验证的配套备份。不要单独删除 WAL/SHM、删除数据库以绕过错误，或用新操作 ID 重试结果不确定的写操作。若错误是数据库被锁定，先确认占锁进程及其事务是否仍在运行，待锁释放后再启动管理器。

## 超时与协议

核心连接排空沿用 `shutdown_timeout_secs`。每次外部系统命令最多等待 5 秒，超时终止并回收子进程。日志写入使用有界非阻塞队列，统计丢弃行数；退出刷新最多等待 2 秒。Web 网关优雅退出最多等待 5 秒。

本轮核心与本地管理 bincode API 为 **5**，独立服务端管理协议为 **2**，Unix 提权交接协议为 **3**，生命周期身份结构版本为 **1**。请将管理器、核心和界面随同一构建包更新；不兼容版本必须更换配套程序，不能通过修改运行清单版本绕过检查。

## 验证边界

自动化回归覆盖关键任务错误/panic/提前返回、原操作 ID 查询、日志拥塞、系统命令超时、进程身份不符、候选退出、管理器强杀接管、恢复助手存活，以及不确定网络记录的保留。Windows 和 Linux 编译/测试不能替代真实网络设置验收。

| Python / Web | Python 20 项测试和架构检查；Web 27 项测试、类型检查、构建，以及 Rust/TypeScript 契约一致性检查 |

Linux 的两项既有进程归属测试在并行编译的高负载下触及查询时限，单独执行及完整串行复跑均通过。忽略项中的恢复助手子进程入口由父测试实际启动；手动基准不计入验收。本轮未改变宿主机真实系统代理或路由。

追加重载/锁中毒审查验证：Windows IPC 26、Protocols 21、Proxy 124、管理存储 10、数据库执行线程 2 项通过；3 项真实进程回归覆盖运行开关与重载、当前/排空代际切组断连，以及更新失败回滚和 A→B→A 切换保留连接。Linux Proxy 121、管理存储 10、数据库执行线程 2 项通过。Proxy 的 2 个既有 fixture 忽略；Linux 另有 1 个最大 UDP 包用例单独标记为环境受限，Windows 已通过该用例。WSL 中独立 Python 原生 UDP loopback 同样无法收到 65507 字节数据报，小包正常，因此该平台结果不包含最大数据报验收；未降低生产包长度限制或更改该用例断言。

新增故障注入覆盖重载等待期限、队列满日志、发布方 panic、锁中毒时的会话取消与清理、提交前取消、确认丢失、回滚失败、数据库锁竞争和无效文件保留。并行任务在同一工作区修改监控接口及运行构建，因此追加验证使用已经生成并确认包含对应测试的程序直接执行；重复排队的本任务构建已取消，不将其列为新的全工作区构建通过记录。
