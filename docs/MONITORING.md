# 内置调试监视器

监视器同时观察核心内部统计和操作系统进程资源，通过现有私有管理 IPC 或已认证的 Web 管理连接读取，不新增监听端口。

## 打开与操作

- Web：选择受控节点和实例，打开「监视器」。可以调整采样间隔、暂停/继续、清空界面历史，以及导出 JSON。浏览器标签页隐藏时暂停采样。
- TUI：在配置档页选中实例，或在其他页面使用当前代理/服务端实例，按 `F9`；也可以在命令面板选择性能/内存/网络监视器。`Space` 暂停/继续，`c` 清空历史，方向键和 `PageUp` / `PageDown` 滚动，`Esc` / `F9` 关闭。

两个界面均最多保留 120 个采样点。TUI 每秒采样一次；关闭监视器后停止该视图的采样。清空历史只清除界面记录，不重置核心内部计数。TUI 暂不提供导出，调试文件从 Web 导出。

## 程序内部统计

| 子系统 | 统计内容 |
| --- | --- |
| 路由 | 决策开始/完成/错误/取消、进行中数量、累计耗时，直连/代理/拦截结果，决策缓存命中/未命中/绕过/写入 |
| 规则 IPC | 请求与排队的数量、进行中数量和耗时，连接尝试、重试、I/O 错误、截止时间超时 |
| 规则核心 | 匹配与回复的数量/耗时/错误，决策结果，无效请求、解码错误、IPC 连接数、规则版本及重载统计 |
| DNS | 应答、真实解析及上游交换的数量/耗时/错误/取消，缓存命中/未命中/过期/驱逐，Fake-IP 应答，限流拒绝与超时 |
| 服务端 | 接受/拒绝/活跃连接，连接及 UDP 配额剩余量，UDP 缓冲预算，监听器、连接任务和日志缓冲数量，重载统计 |
| 控制接口与宿主 | 控制请求队列、任务及连接数量，宿主代际、活动代、暂停状态、失败 worker、流数量与未能采样的 worker |

内部指标采用固定名称，不把域名、连接 ID 或请求内容作为标签。指标在对应代码路径首次执行时注册；尚未出现的指标代表没有注册，不能据此推断功能异常。热重载保留进程内累计计数，进程退出后清零；`epoch` 标识统计周期。

`counter` 是累计值，`gauge` 是当前值。操作的 `completed` 包含成功与错误，`failed` 是其中的错误数；`cancelled` 单独记录被取消或中断的操作。`duration_us` 是已完成操作的累计微秒耗时，不包含取消的操作；除以同组 `completed` 得到累计平均耗时。异步操作耗时包含等待和排队，并非纯 CPU 时间，也不是 p95/p99 延迟。

Web 对同一周期中的相邻整数计数计算每秒增量，使用各指标自身的采样时间，避免慢 worker 回应影响速率；没有指标时间戳时不显示速率。保留原始十进制字符串，避免大计数超过 JavaScript 精度范围。采样不是所有计数器的事务快照，短暂并发变化可能造成指标间微小不一致。

使用常驻宿主/worker 时，宿主查询同时读取存活 worker，指标以 `workers.<generation>.` 区分，防止跨代计数混合；不可达 worker 不用旧数据冒充新样本，单独报告数量。已退出 worker 的内部计数不保留为历史累计量。

## CPU、内存与网络

TUI 概览右侧「快照」第二行显示会话累计代理/直连流量（上传＋下载），以及当前出口节点的累计代理流量。`b` 循环切换节点统计周期：`this session → 1h → 24h → 7d → 1mon → persist`。`S P`/`D` 分别表示会话代理/直连；中文显示「会话 代」/「直」。单位采用 1024 进制，`K/M/G/T/P/E` 为缩写，无后缀表示字节。

会话指当前代理宿主的运行周期，重新打开 TUI 不会清零，宿主重启则重置；热重载和 worker 切换延续计数。节点按当前配置档内的实际出站标签独立记账，包含已关闭的 TCP/UDP 连接，不会把其他节点或直连流量算到当前节点。`1h/24h/7d/1mon` 为滚动窗口，`1mon` 固定为最近 30 天，以一分钟为时间桶（边界精度一分钟）；`persist` 为启用此功能以来保存的全部累计量。

节点历史由常驻宿主采样，关闭界面仍持续统计，保存在该配置档对应的 runtime `traffic-history` 文件中，每 30 秒原子保存一次。异常退出可能丢失最后一次保存后的增量；退出 worker 最后未能采样的字节也无法补回。旧核心或采样不完整时节点统计显示 `—`，不会用活跃连接求和冒充累计量；`~` 表示显示上次数据。历史无法读取或保存时保留原文件，历史周期显示 `—`，本次会话仍可计数。

CPU 和内存仅属于所选受管 PID。CPU 的 100% 表示一个逻辑核心，多线程进程可以超过 100%；第一份样本不足以计算 CPU。RSS/Working Set 为当前驻留内存；Linux/macOS 另提供虚拟地址空间大小，Windows 此项显示不可用。托管模式下，这些进程资源数值不包括 worker 子进程。

网络显示核心已有的累计上传/下载字节、活跃及累计连接数，以及相邻样本计算的速率。它代表代理转发统计，不是整机网卡流量或抓包；规则核心不提供网络流量。部分宿主流量统计会汇总 worker，与上面仅一个 PID 的 CPU/内存范围不同。

进程切换、重启、计数回退、暂停后继续和采样失败会重建速率基线。无法采集的字段显示 `—`；错误和最后采样时间保留在界面上。Windows 本机测试不能替代 Linux/macOS 实机验收。

## 调试数据与扩展

Web JSON 导出包含节点/实例标识、时间戳、采样配置、资源数值、内部原始指标和派生速率，不包含登录令牌或配置文档。历史只保存在当前界面内存，导出由用户主动触发。

新增内部指标使用 `astra-observe` 的固定名称 `counter!`、`gauge!` 或 `operation!`。注册后热路径只更新原子计数；操作 guard 在取消时释放进行中计数。不要为用户输入动态创建指标，或在每个转发数据包中生成快照。该库不创建后台线程、不执行 I/O，也不记录数据包内容。

相关验证：

```sh
cargo test -p astra-observe -p astra-platform -p astra-ipc -p astra-manager -p astra-tui monitor
cargo test -p astra-dns
cargo test -p astra-server-core monitor
cd apps/web
npm test
npm run build
npx playwright test --config playwright.monitor.config.ts
```

Playwright 监视器测试使用确定性的管理响应测试界面操作与下载；Rust 测试负责原生采样、内部计数、管理契约及核心入口。
